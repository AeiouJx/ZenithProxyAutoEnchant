### 6.1 砂轮：常驻，不补给
- 删 `RESTOCK_GRINDSTONE_GO_TO_CHEST` / `..._WITHDRAW` / `..._AWAIT_WITHDRAW` 三态与实现。
- 交互前校验：`World.getBlock(config.grindstone)` 必须是 `grindstone`；不符 → `fail("grindstone missing at x,y,z")`，**不许**在附近找替代砂轮。

### 6.2 铁砧：没了才补
```
EVAL_ANVIL：config.anvil 处是铁砧？
  是 → 取书
  否 → 从 anvilChest 取 anvilRestockStacks 叠铁砧 → 放到 config.anvil → 回读确认 → 取书
anvilChest 未设或空箱 → AWAIT_RESTOCK（退避 ≥20 tick）+ problem
```
`CRAFT_ANVIL_BLOCKS`（铁块合成铁砧）本阶段不实现，删掉相关分支。

### 6.3 是否祛魔（唯一判断点，在取货之后、进铁砧之前）
```
impurity = 背包里该装备的词条 − itemEnchantments（忽略诅咒）
impurity 非空 && allowGrindstone && 砂轮就绪  → 祛魔
impurity 非空 && !allowGrindstone             → 不祛魔，进铁砧；失败原因注明 "impurity kept: allowGrindstone=false"
impurity 非空 && 砂轮缺失                      → fail("grindstone missing at …")
否则                                          → 不祛魔
```

### 6.4 经验（`experienceSource`）
| 值 | 行为 |
| --- | --- |
| `NONE` | 不动、不开 KillAura；每 `NO_XP_TIMEOUT_MS`(60000) 一条 warn |
| `KILL` | 未到 `killSpot` → `BARITONE.pathTo`；到达（水平 ≤3 / 垂直 ≤4）→ `CONFIG.client.extra.killAura.enabled = true; MODULE.get(KillAura.class).syncEnabledFromConfig();` 记 `ownsActivation`；够了还原原值 |
| `EXP` | 只寻路到 `killSpot`，**全程不开** KillAura，等 `experienceLevel` 上升 |

硬规则：进铁砧前必须 `stopOwnedKillAura()`；`reset()`/`onDisable()`/死亡/断线必须归还；血量 < 12 停刷。字段名是 `killAura`（驼峰）。

### 6.5 延时与退避
- `operationDelay`（tick）：右击→首次点击、点击→点击、放置→下一动作。
- `waitForInteractTimeoutTicks`（tick）：等开窗 + 等界面就绪。
- `AWAIT_RESTOCK`：`max(restartDelay, 20)` tick，**不能直接用 `restartDelay=5`**，否则每 250ms 重开一次箱子。

### 6.6 一件装备结束去哪里
| 结果 | 去向 |
| --- | --- |
| 成功 | `outputChest`（与 `postEnchantStoreMode` 无关） |
| 失败 | `overflowChestPos` → 未设则 `outputChest` → 都没有则留包 + warn（永不丢弃） |
| `TO_RESTOCK` | 多余输入回 `inputItemChest`，成品仍进 `outputChest` |
| `NONE` | 只靠背包满时的 STORE 流程统一卸到 `outputChest` |

## 8. 序列化 / 校验 / 注册

### 8.1 `AutoEnchantConfigSerializer`
现状会编译失败（`AutoEnchantConfig.parsePos` 已删）。改成自带坐标解析，**不要**往 config 里加静态方法：

```java
private static final BlockPos ZERO = BlockPos.ZERO;
private static BlockPos pos(JsonElement e) {   // 支持 {"x":..} 与 "x,y,z" 与 "(x, y, z)"
    if (e == null || e.isJsonNull()) return ZERO;
    if (e.isJsonObject()) { var o = e.getAsJsonObject();
        return new BlockPos(o.get("x").getAsInt(), o.get("y").getAsInt(), o.get("z").getAsInt()); }
    if (e.isJsonPrimitive()) {
        String s = e.getAsString().replace("(", "").replace(")", "").trim();
        if (s.isEmpty()) return null;                    // 让调用方删字段
        String[] p = s.split("[,\\s]+");
        if (p.length < 3) return null;
        return new BlockPos(Integer.parseInt(p[0]), Integer.parseInt(p[1]), Integer.parseInt(p[2]));
    }
    return null;
}
```

`normalize(JsonObject root)` 规则（按序、幂等、解析失败删字段走默认）：

| # | 旧 | 新 |
| --- | --- | --- |
| 1 | 坐标字段是字符串 | 转 `{"x","y","z"}` 对象；空串 / 坏值 → **删字段** |
| 2 | `jobs[]` | `enchants{}`，key = item 短名（重名加 `_2`） |
| 3 | job 内 `enchantments[]`（`{id,level}`） | `itemEnchantments{id:level}` |
| 4 | `enchantItem` / `inputChest` / `semiFinishedChest` / `postJobStoreMode` | `item` / `inputItemChest` / `overflowChestPos` / `postEnchantStoreMode` |
| 5 | 站点 `outputChest` / `semiFinishedChest` / `grindstoneChest` | 丢弃（`outputChest` 下沉到各 job 时优先用 job 自己的） |
| 6 | `containerPositions` | `enchantBook` |
| 7 | `anvilPositions` / `grindstonePositions`（数组） | 取第一个非零项 → `anvil` / `grindstone` |
| 8 | `operationDelayMs` / `restartDelayMs` / `interactDelay` | 丢弃（毫秒不可无损转 tick，走默认 5/5） |
| 9 | 其余已删字段 | `remove` |

写 `configVersion: 2`。**空字符串坐标必须删字段**——`"outputChest": ""` 会让 Gson 抛 `Expected BEGIN_OBJECT`，代理直接 `System.exit(1)`（已踩过）。

### 8.2 `AutoEnchantConfigValidator`
- 全局：`waitForInteractTimeoutTicks ∈ 1..1200`；`operationDelay ∈ 0..40`；`restartDelay ∈ 1..200`；`anvilRestockStacks ∈ 1..8`；`scanHorizontalBlocks ∈ 1..256`；`scanVerticalBlocks ∈ 1..64`；`experienceSource != null`。

## 10. 坑（踩过的，别再踩）

1. `Command.enumStrings(Enum<?>[])` **是存在的**（`com.zenith.command.api.Command:86`），返回小写名；`ExperienceSource.valueOf(getString(...).toUpperCase())` 这样还原。
2. `executes` 有两个重载（`IExecutes` 返回 void / brigadier `Command` 返回 int），写 `c -> { return OK; }` 才能落到 `Command`；写成 `c -> OK` 或方法引用会歧义。
3. `BlockPos` 是 record：`new BlockPos(x,y,z)`、`addY(1)`，不能给 `.x()` 赋值。
4. `Object2IntLinkedOpenHashMap<String>` 只有 **1 个**泛型参数（value 固定 int）。
5. `Enchant.getRenameName()` 返回 `ItemData` 但 `renameName` 是自由文本 → 删掉此方法（命令已不调用）。
6. `run` 的坐标必须 `BlockPos`；配置里出现坐标字符串就是 bug。
7. `AWAIT_RESTOCK` 的 `max(restartDelay, 20)`：`restartDelay` 默认 5 tick，直接当退避会 4 次/秒刷空箱。
8. 扫描每 5 秒一次会覆盖手改词条 → 必须内存签名去重（§5.2）。
9. `add` 的 `item` 参数必须是 `item()`，不能用 `EquipmentType`（类型无法定位具体物品，`ItemRegistry` 查不到会 NPE）。
10. 任何写 config 的地方都要 `Globals.saveConfigAsync()`；否则重启后丢失。
