# AutoEnchant 重构实施方案 v3（对齐 2026-11-13 最新 config）

> 交接 opencode。v1（`docs/重构方案.md`）按旧模型写，已作废；本文件覆盖 v2 并在其基础上对齐你刚精简过的 `AutoEnchantConfig`。
> 命令层由你自己修一版，本方案只给「最终契约 + 必须修的 bug 清单」。

| 项 | 规则 |

### 0.1 本次 config 变更 → 影响面（先看这张表）

| 变更 | 影响 |
| --- | --- |
| 新增 `BlockPos grindstone` / `BlockPos anvil` | 站点坐标从「扫描列表」变「单点」：`scan` 只写**最近一个**（字段为 `ZERO` 时）；手填后不被覆盖，方块消失时按失败处理，不静默换点 |
| `containerPositions` → `LinkedHashMap<String, BlockPos> enchantBook` | 附魔书补给箱按附魔 id 存；**类型已是 BlockPos**，序列化迁移量减半 |
| `operationDelayMs(250)` → `operationDelay(5 ticks)` | 单位从毫秒变 tick；`Thread.sleep`/`currentTimeMillis` 全部改 `Timer.tick` |
| `restartDelayMs(3000)` → `restartDelay(5 ticks)` | 退避从 3 秒变 250ms —— **必须**在 `AWAIT_RESTOCK` 里取 `max(restartDelay, 20)`，否则空箱会被刷爆（§6.7） |
| 删除 `scanIntervalTicks` / `windowSettleDelayMs` / `windowTimeoutMs` | 变常量：`SCAN_INTERVAL_TICKS=100`、`WINDOW_SETTLE_TICKS=2`、`WINDOW_TIMEOUT_TICKS=100` |
| 删除 `reserveLevels` / `minimumHealth` / `noXpTimeoutMs` / `allowedXpDimensions` | 变常量：`RESERVE_LEVELS=2`、`MIN_HEALTH=12`、`NO_XP_TIMEOUT_MS=60_000`；维度检查去掉 |
| 删除 `discardFailedTransactionItems` | 失败品**永不丢弃**：无可用箱 → 留包 + `warn` |
| 删除 `presetImpurityPolicy` / `customImpurityPolicy` | 祛魔判定简化成「`allowGrindstone` + 是否有 target 外杂质」，§6.4 |
| 删除 `interactDelay` | 由 `operationDelay` 承担 |
| `experienceSource` 行仍缺 `;` | 不补，项目一行都编译不了 |

## 1. 十一条决策 → 落点

| # | 决策 | 落点 | 验收点 |
| --- | --- | --- | --- |
| 1 | `grindstoneChest` = 砂轮补给箱 | 站点级字段；红石粉展示框下方容器写入 | `scan` 后等于红石粉框下方箱 |
| 2 | 失败品走 `TO_OVERFLOW` | `POST_ENCHANT` 失败分支固定 `TO_OVERFLOW`（§6.5） | 做坏一件 → 出现在 overflow 箱 |
| 3 | `scan` 自动 `overflowChestPos = outputChest` | `EnchantStationScanner` 导入作业时同步 | scan 后两者 xyz 相同 |
| 4 | 不保留 `renameOrder` | 改名固定挂第一次合并（`operationIndex == 0`） | grep 无 `renameOrder` |
| 5 | `semiFinished` 概念删除 | 字段/角色/命令/文案/worker 分支全删；红石粉改指砂轮补给 | grep 无 `semiFinished`、`semi_finished` |
| 6 | `EXP` = 站 `killSpot` 不攻击，只吸经验球 | `EnchantXpFarm` 只寻路 + 等 `experienceLevel` 上升 | `EXP` 下 KillAura 全程关 |
| 7 | `KILL` = 走到点 → 开 KillAura → 够了关 | 现有 `syncEnabledFromConfig()` + 归还逻辑保留 | 结束恢复开启前状态 |
| 8 | `NONE` = 等级不够退避 + 周期提示 | `AWAIT_RESTOCK` + `NO_XP_TIMEOUT_MS` 周期提示 | 不刷怪、不刷屏 |
| 9 | `supplyDepth` 不要 | 常量 `SUPPLY_SCAN_DEPTH = 8` | grep 无 `supplyScanDepth` |
| 10 | `awaitIntactTimeout` → `waitForInteractTimeoutTicks` | 全局统一用该字段 | grep 无 `awaitIntactTimeout` |
| 11 | `EquipmentType` 用于 scan 判「是不是装备」 | `EquipmentType.of(ItemData)` 替代 `MAX_DAMAGE` | 装饰品框不生成作业 |

另：`add` 坐标必填（`scan` 才是自动路径）；附魔书补给箱存 `enchantBook`。

### 2.2 必须修的字段问题

| 位置 | 问题 | 改法 |
| --- | --- | --- |
| `AutoEnchantConfig.java:32` | `experienceSource = ExperienceSource.KILL` 缺 `;`，整项目停在这行 | 补 `;` |
| `Enchant.getRenameName()` | 返回 `ItemData`，`renameName` 是自由文本，`ItemRegistry` 必查不到；无合法调用 | 删方法 |
| `AutoEnchantConfig.Enchantment` | `itemEnchantments` 已是有序 map，POJO 无引用 | 删类 |

### 2.3 「模式」运行时派生（关键设计）

配置只存一份目标词条，`PRESET` / `CUSTOM` 由 `matchPreset` 派生：

```java
Map<String, Integer> target = new LinkedHashMap<>(enchant.itemEnchantments);
String preset = catalog.matchPreset(enchant.item, target);   // 完全相等才命中
if (preset != null) {
    operations = catalog.operations(preset, enchant.item);   // 指南合并树（最优）
} else {
    var plan = CustomEnchantPlanner.plan(enchant.item, current, penalty, target);
    operations = plan == null ? List.of() : plan.operations();
}
if (operations.isEmpty()) fail("no merge order fits the 39-level limit");
```

好处：`scan` 拆出的词条、`outputEnchants add/del` 改的词条、执行目标三者同一份数据，不需要两套模型。

### 2.4 扫描不覆盖手改（内存签名，不写盘）

```java
private final Map<String, String> importedSignatures = new HashMap<>(); // jobId -> 词条串|名称

String sig = frame.enchantments().entrySet().stream()
    .sorted(Map.Entry.comparingByKey())
    .map(e -> e.getKey() + "=" + e.getValue())
    .collect(Collectors.joining(",")) + "|" + Objects.toString(frame.customName(), "");
if (!sig.equals(importedSignatures.get(jobId))) {
    enchant.itemEnchantments.clear();
    frame.enchantments().forEach(enchant.itemEnchantments::put);
    enchant.renameName = frame.customName() == null ? "" : frame.customName();
    enchant.renameEnabled = !isBlank(enchant.renameName);
    importedSignatures.put(jobId, sig);
}
```

约定：**进程重启后首次 scan 必重导一次**（展示框是说明书）。写进 README。

附魔书识别：

```java

if (stored != null) stored.getEnchantments().keySet()
    .forEach(id -> PLUGIN_CONFIG.enchantBook.put(id, containerPos));
```

### 5.2 站点方块（`anvil` / `grindstone`）

```
扫描半径内找 anvil / grindstone 方块：
  取离 BOT 最近的一个（先水平距离平方，再比 y 差）
  if (config.<role> == BlockPos.ZERO) config.<role> = 最近点     // 只补空
  否则保留手填值；若该点方块已不是对应方块 → problem("anvil at x,y,z is gone")，运行时按失败处理
```

替代旧 `anvilPositions` / `grindstonePositions` 列表：执行层永远只用单点，扫描结果只用于补空与排错。

### 5.3 `EquipmentType.of(ItemData)`（放在 `AutoEnchantModule.EquipmentType` 内，保持 command 现有 import）

```java
public static EquipmentType of(@Nullable ItemData data) {
    if (data == null) return NONE;
    String n = data.name();
    if (n.startsWith("minecraft:")) n = n.substring(10);
    if (n.endsWith("_helmet")) return HELMET;
    if (n.endsWith("_chestplate")) return CHESTPLATE;
    if (n.endsWith("_leggings")) return LEGGINGS;
    if (n.endsWith("_boots")) return BOOTS;
    if (n.endsWith("_pickaxe")) return PICKAXE;   // 必须先于 _axe，否则 pickaxe→AXE
    if (n.endsWith("_shovel")) return SHOVEL;
    if (n.endsWith("_hoe")) return HOE;
    if (n.endsWith("_sword")) return SWORD;
    if (n.endsWith("_axe")) return AXE;
    return switch (n) {
        case "bow", "crossbow", "trident", "mace", "spear", "fishing_rod", "shears",
             "flint_and_steel", "shield", "carrot_on_a_stick", "warped_fungus_on_a_stick",
             "brush", "elytra" -> valueOf(n.toUpperCase(Locale.ROOT));
        default -> NONE;
    };
}
public static boolean isEquipment(ItemData data) { return of(data) != NONE; }
```

- `NONE` 的框不生成作业（替代 `MAX_DAMAGE` 判定），`MAX_DAMAGE` 保留为二次确认。
- `SPEAR` 在 1.21.4 可能不存在 → 匹配不到自然落 `NONE`，不抛异常。
- `JobFrame` 增加 `EquipmentType type`，`jobDetails()` 输出 `[SWORD] diamond_sword`。

### 5.4 作业导入（applyJobFrames）

```
对每个 jobFrame：
  id = item 短名；已存在同名作业 → 复用（保留手填坐标/策略），否则新建
  e.item = frame.item
  if (signature 变化) → 重写 itemEnchantments / renameName / renameEnabled
  if (e.inputItemChest 未设置) e.inputItemChest = frame.containerPos()
  if (站点 outputChest 已发现) { e.outputChest = 站点 outputChest; e.overflowChestPos = e.outputChest; }
  if (frame.lampOn() != null) e.enabled = frame.lampOn()
  if (e.postEnchantStoreMode == NONE) e.postEnchantStoreMode = TO_OVERFLOW
```

容器解析沿用 `resolveContainer(frame)`：向下扫**第一个**容器，深度 `SUPPLY_SCAN_DEPTH = 8`，接受箱子/陷阱箱/木桶/任意潜影盒；未加载区块跳过不报错。

### 5.5 不变量

- `scan` 只写 config + 缓存 `markers/stations/jobFrames/problems`，不碰事务；事务中只记 pending，`POST_ENCHANT` 后应用。
- 同一 `enchantBook` key 两个书框指向不同坐标 → 保留第一个 + `problem`。
- 坐标不出现 `String`。

### 6.2 状态职责与迁移

| State | 动作 | 成功 → | 失败/超时 → |
| --- | --- | --- | --- |
| ENTRYPOINT | `EnchantIterator` 取 `enabled && complete` 的 job，清事务字段 | `EVAL_RESTOCK` | 无 job：`status="idle (no runnable job)"` 停留 |
| EVAL_RESTOCK | `countItem(item)`；背包空位 `< 2` | 有货 → `EVAL_UNCHANT`；缺货 → `RESTOCK_INPUT_GO_TO_CHEST`；满 → `STORE_GO_TO_CHEST` | `inputItemChest` 未设 → `AWAIT_RESTOCK` |
| RESTOCK_INPUT_GO_TO_CHEST | `BARITONE.rightClickBlock(...)`，重置 `waitForInteractTimer` | `RESTOCK_INPUT_WITHDRAW` | 寻路拒绝/超时 → `AWAIT_RESTOCK` |
| RESTOCK_INPUT_WITHDRAW | 等开窗；`withdraw(id == item, inputItemRestockStacks)` + `CloseContainer` | `RESTOCK_INPUT_AWAIT_WITHDRAW` | 未开：`waitForInteractTimeoutTicks` 后重开（≤2 次） |
| RESTOCK_INPUT_AWAIT_WITHDRAW | `awaitContainerClosed()`；`countItem > 0` | `EVAL_UNCHANT` | 仍 0：重试 ≤2，否则 `AWAIT_RESTOCK` |
| EVAL_UNCHANT | 解析 plan（§2.3）；判定是否祛魔（§6.4） | 祛魔 → `RESTOCK_GRINDSTONE_GO_TO_CHEST`；否 → `RESTOCK_ANVIL_GO_TO_CHEST` | 无 plan → `fail()` |
| RESTOCK_GRINDSTONE_* | `grindstone` 方块缺失时从 `grindstoneChest` 取砂轮并放置 | `GRINDSTONE_INTERACT` | 空箱 / `allowGrindstone=false` → `fail()` / `AWAIT_RESTOCK` |
| GRINDSTONE_INTERACT / AWAIT | 右击砂轮；`operationDelay` 后放左槽 | `GRINDSTONE_TAKE` | 3 次失败 → `fail()` |
| GRINDSTONE_TAKE / AWAIT | 取回物品，校验词条已清空 | `RESTOCK_ANVIL_GO_TO_CHEST` | 词条仍在 → `fail()` |
| RESTOCK_ANVIL_* | `anvil` 缺失：从 `anvilChest` 取铁砧；只取到铁块 → `CRAFT_ANVIL_BLOCKS` | `ENCHANT_INTERACT_WITH_ANVIL` | 空箱 → `AWAIT_RESTOCK` |
| CRAFT_ANVIL_BLOCKS / AWAIT | 2×2 合成 + 放置 | `ENCHANT_INTERACT_WITH_ANVIL` | 合成失败 → `fail()` |
| RESTOCK_ENCHANTED_BOOK_* | 按 plan 下一本书的 id 查 `enchantBook`，开箱取 1 本 | `ENCHANT_INTERACT_WITH_ANVIL` | 该 id 无坐标 → `fail("no book chest for <id>")` |
| ENCHANT_INTERACT_WITH_ANVIL / AWAIT | 右击铁砧 | `ENCHANT_TRY_START` | 超时重试 ≤2 |
| ENCHANT_TRY_START | 放左输入、右牺牲；`operationIndex==0 && renameEnabled` 时写名字槽 | `AWAIT_ENCHANT` | 槽被占/预览不符 → `fail()` |
| AWAIT_ENCHANT | 等 `REPAIR_COST` 数据包；费用 > 当前等级 → `CLOSE_FOR_XP`；否则点输出槽 | 还有步骤 `NEXT_ENCHANT`；完成 `READY_NEXT_ENCHANT` | 39 级上限/预览不符 → `fail()` |
| CLOSE_FOR_XP | 关铁砧窗（保住输入槽） | `WAIT_XP` | — |
| WAIT_XP | `EnchantXpFarm.ensureLevels(cost)` | 够了 → `ENCHANT_INTERACT_WITH_ANVIL` | 中断 → `fail("xp interrupted")` |
| STORE_GO_TO_CHEST / DEPOSIT / AWAIT | 背包将满，卸非本作业物品到 `outputChest` | `EVAL_RESTOCK` | 箱满 → `warn` + 继续 |
| READY_NEXT_ENCHANT | 校验词条 == target | `POST_ENCHANT` | 不符 → `fail()` |
| NEXT_ENCHANT | 推进 `operationIndex` / `bookIndex` | 需书 → `RESTOCK_ENCHANTED_BOOK_GO_TO_CHEST`；否则 `ENCHANT_INTERACT_WITH_ANVIL` | — |
| POST_ENCHANT | 按 §6.5 决定去向 | `POST_ENCHANT_*` 或 `ENTRYPOINT`（NONE） | — |
| POST_ENCHANT_* | 存 1 件 | `ENTRYPOINT` | 无坐标/箱满 → 留包 + `warn` |
| AWAIT_RESTOCK | 退避 `max(restartDelay, 20)` tick | 到时 → `ENTRYPOINT` | — |

### 6.3 通用规则

- **关窗不是状态**：每个 `*_AWAIT_*` 开头 `if (!awaitContainerClosed()) return;`（照 trader `:2349`），删掉 worker 的 `WAIT_CLOSE` / `CLOSE_*`。
- **`operationDelay`（tick）**：右击→首次点击、点击→点击的统一间隔；禁止再用 `Thread.sleep`。
- **窗口超时**：`WINDOW_TIMEOUT_TICKS = 100`（原 `windowTimeoutMs=5000`）；交互超时用 `waitForInteractTimeoutTicks`。
- **重试上限**：取货 2、铁砧恢复 3、砂轮 2（常量集中 `AutoEnchantConstants`）。
- **失败收敛**：`fail(reason)` 只做三件事：记 `failureReason`、`stopOwnedKillAura()`、`setState(POST_ENCHANT)`。

### 6.4 是否需要祛魔（EVAL_UNCHANT 唯一判断点）

策略字符串已随 config 删除，规则固定为：

```
current  = 背包里该装备的词条
target   = job.itemEnchantments
impurity = current 中不在 target 里的词条（忽略 curses；mending 等非合并项不算）

if (!allowGrindstone)            → 不祛魔（杂质留着，可能直接 fail）
else if (impurity 非空)          → 祛魔（杂质会拖高费用且无法消掉）
else if (matchPreset == null && current 部分满足 target && priorWorkPenalty > 0)
                                 → 续做，不祛魔
else                             → 不祛魔
```

### 6.5 结束一件装备：去哪（`postEnchantStoreMode` 语义）

| 结果 | 去向 |
| --- | --- |
| 成功（词条 == target） | 固定 `outputChest`（与 `postEnchantStoreMode` 无关） |
| 失败（词条不符 / 缺书 / 费用超限 / 铁砧恢复失败） | 固定按 `TO_OVERFLOW`：`overflowChestPos` → 未设则 `outputChest` → 都没设则**留包 + `warn`**（`discardFailedTransactionItems` 已删，不丢弃） |
| `TO_RESTOCK` | 多余输入（同物品未完批次）存回 `inputItemChest`；成品仍进 `outputChest` |
| `NONE` | 不额外卸货，靠背包满时 `STORE_*` 统一卸到 `outputChest` |

`scan` 会把 `overflowChestPos` 设成与 `outputChest` 同坐标，因此默认「成功失败同一成品箱」，失败品不会混回待附魔队列（它在 output，不在 input）。

### 6.6 经验（EnchantXpFarm）

```java
public enum Mode { NONE, KILL, EXP }   // ← config.experienceSource
boolean ensureLevels(int needed);      // 每 tick 调一次
void stopOwnedKillAura();              // 归还
boolean consumeInterruption();
```

| Mode | 行为 |
| --- | --- |
| `NONE` | 不移动、不开 KillAura；每 `NO_XP_TIMEOUT_MS` 一条 `warn("need {} levels, waiting (experienceSource=NONE)")` |
| `KILL` | 未到 `killSpot` → `BARITONE.pathTo`；到达（水平 ≤3 / 垂直 ≤4）→ `CONFIG.client.extra.killAura.enabled = true; MODULE.get(KillAura.class).syncEnabledFromConfig();` 记 `ownsActivation`；够了 → 还原原值 |
| `EXP` | 只寻路到 `killSpot`，**不开** KillAura；等 `experienceLevel` 上升；`NO_XP_TIMEOUT_MS` 无增长 → `warn` 并继续等 |

硬规则：
- 进 `ENCHANT_INTERACT_WITH_ANVIL` 前必须 `stopOwnedKillAura()`。
- `reset()` / `onDisable()` / 死亡 / 断线必须归还。
- 血量 < `MIN_HEALTH`（12）→ 停刷 + `warn`。
- 维度检查无配置字段 → 不做（留注释说明）。
- 无 `killAuraMaxSeconds` → 无强制超时，唯一超时是「无经验增长」。

字段名：`CONFIG.client.extra.killAura.enabled`（驼峰 `killAura`，不是 `killaura`）。

## 8. 校验器规则（`AutoEnchantConfigValidator`）

全局：

- `waitForInteractTimeoutTicks ∈ 1..1200`；`operationDelay ∈ 0..40`；`restartDelay ∈ 1..200`
- `anvilRestockStacks ∈ 1..8`
- `experienceSource != null`
- `enchants` 至少一个 `enabled`（否则提示 `scan` 或 `set <id> on`）
- `enchantBook` 每个 value 非 `ZERO`；key 在 `EnchantmentRegistry` 中存在
- `anvil`/`grindstone`：已设置但该点方块类型不符 → 报「station gone」，不阻塞其他作业

单作业（`problemsFor(id)`）：

- `item` 能解析到 `ItemData` 且 `EquipmentType.of() != NONE`
- `inputItemChest` / `outputChest` 已设置（`ZERO` = 未设置）
- `itemEnchantments` 非空；key 合法、`1 <= level <= maxLevel`；无互斥词条（`catalog.hasConflict`）
- `renameEnabled` → `renameName` 非空且 ≤50 字符
- `postEnchantStoreMode == TO_OVERFLOW` → `overflowChestPos` 已设置（`scan` 会补；手填 `add` 要提示）
- `inputItemRestockStacks ∈ 1..35`
- 预跑 `resolvePlan()`：无解（39 级上限 / 缺书 / 缺 bookChest）→ 直接进 `problems`，不等运行时
