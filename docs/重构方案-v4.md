## 0. 字段语义定稿（本版核心）

你给的 12 条语义，逐条落到「谁写 / 谁读 / 校验」：

| 字段 | 唯一语义 | 谁写 | 谁读 | 校验 / 失败表现 |
| --- | --- | --- | --- | --- |
| `grindstone` | 你**预先放好的砂轮方块坐标**，程序只走过去交互，**不放置、不补货** | 手填 `grindstone <x y z>` | `GRINDSTONE_INTERACT` | 该点方块不是 `grindstone` → `problem("grindstone missing at …")`；`allowGrindstone=true` 且需要祛魔时 → `fail` |
| `anvil` | 铁砧**放置点兼交互点**。方块没了就从 `anvilChest` 取铁砧放回这里 | 手填 `anvil <x y z>`；放置流程会写回实际落点 | `EVAL_ANVIL` / `ENCHANT_INTERACT_WITH_ANVIL` | 该点无铁砧 → `RESTOCK_ANVIL_*`；箱空 → `AWAIT_RESTOCK` |
| `anvilChest` | **铁砧补给箱**。铁砧被磨坏后从这里取备用铁砧 | `scan`（铁块展示框下方第一个容器）/ 手填 | `RESTOCK_ANVIL_WITHDRAW` | 未设置 → 铁砧坏了只能 `fail`，不静默 |
| `anvilRestockStacks` | 铁砧**补货叠数**：从 `anvilChest` 一次取出几叠（1–8） | 手填 `anvilRestock <1-8>` | `RESTOCK_ANVIL_WITHDRAW` | `<1` 或 `>8` → 校验报错 |
| `actionDelay` | **操作间隔（tick）**：右击→首次点击、点击→点击、放置→下一个动作 | 手填 `operationDelay <ticks>` | 全状态机 | `0..40`；**是 tick 不是 ms** |
| `restartDelay` | **流程卡住后的重启延时（tick）**：`fail` / `AWAIT_RESTOCK` 的退避基数 | 手填 `restartDelay <ticks>` | `AWAIT_RESTOCK` / `POST_ENCHANT` 重入 | `1..200`；实际取 `max(restartDelay, 20)`，见 §6.8 |
| `allowGrindstone` | **装备从取货箱取出后是否允许祛魔**（准入开关，不是「有没有砂轮」） | 手填 `allowGrindstone on/off` | `EVAL_UNCHANT` | `false` → 杂质保留直接进铁砧（可能因成本 `fail`） |
| `waitForInteractTimeoutTicks` | **容器开窗超时 + 铁砧/砂轮界面交互超时**（统一一个值） | 手填 | `*_WITHDRAW` / `*_AWAIT_INTERACT` | `1..1200`；默认 20 tick = 1s，卡顿环境建议 40 |
| `experienceSource` | **经验来源**：`NONE` 不刷 / `KILL` 开 KillAura / `EXP` 只站桩吸经验球 | 手填 | `EnchantXpFarm` | `null` → 校验报错 |
| `enchantBook` | **附魔书 id → 该书存放容器坐标**（`{sharpness: pos}`） | `scan`（附魔书展示框下方第一个容器）/ 手填 `bookChest` | `RESTOCK_ENCHANTED_BOOK_*` | value 为 `ZERO` 或 key 不在注册表 → 校验报错；某书无坐标 → `fail("no book chest for …")` |
| `enchants` | **待附魔装备条目**（一 id 一条：物品 + 取货箱 + 卸货箱 + 目标词条 + 改名 + 落货策略） | `scan` / `add` / `set` | 全部 | 见 §8 |
| `scanHorizontalBlocks` / `scanVerticalBlocks` | 展示框扫描半径（水平/垂直，格） | 手填 `scanRange` | `EnchantStationScanner` | `1..256` / `1..64` |

### 0.1 相对 v3 的语义纠正（必看，写错就是真机事故）

| v3 写的 | v4 改为 | 原因 |
| --- | --- | --- |
| `grindstoneChest` = 砂轮补给箱（红石粉框） | **字段不存在，删除**。砂轮常驻，不消耗、不补给 | 砂轮不会消失，补货逻辑是多余状态 |
| 红石粉展示框 → `grindstoneChest` | **红石粉框废弃**：`scan` 忽略并记 `problem("redstone dust frame has no role")` | 没有落点字段 |
| `scan` 自动回填 `grindstone` / `anvil` 为「最近方块」 | **`scan` 不写这两个坐标**，只校验该点方块类型 | 语义是「你预先放好的位置」，猜最近点会在别人的机器上乱点 |
| `RESTOCK_GRINDSTONE_*`（3 个状态，取砂轮→放砂轮） | 删。砂轮缺失 = `fail`，不做恢复 | 同上 |
| `CRAFT_ANVIL_BLOCKS`（铁块合成铁砧） | 降级为 **P3 可选项**，主路径只做「从 `anvilChest` 取现成铁砧」 | `anvilRestockStacks` 的单位是「叠铁砧」，不是「叠铁块」 |
| `SCAN_RANGE` 常量 | 用 `scanHorizontalBlocks` / `scanVerticalBlocks` | 字段已回到 config |

## 4. 扫描（EnchantStationScanner）

### 4.1 展示框角色表

| 框内物品 | 角色 | 写入 |
| --- | --- | --- |
| 装备（`EquipmentType.of() != NONE`） | `job:<itemShortName>` | `item`、`inputItemChest`（框下第一个容器）、`itemEnchantments`、`renameName/Enabled`、`enabled`（上方红石灯 `LIT`） |
| 红石块 | `output` | 站点输出箱：写**未设置** `outputChest` 的作业，并同步 `overflowChestPos = outputChest` |
| 铁块 | `anvil_supply` | `anvilChest` |
| 附魔书 | `book:<enchantmentId>` | `enchantBook.put(id, 框下第一个容器)` |
| 红石粉 / 其他 | — | **忽略** + `problem("redstone dust frame has no role")` |

容器解析：向下扫**第一个**容器，深度 `SUPPLY_SCAN_DEPTH = 8`，接受箱子/陷阱箱/木桶/任意潜影盒；未加载区块跳过不报错。

附魔书识别：

```java
var stored = shown.getData(DataComponentTypes.STORED_ENCHANTMENTS);   // ItemEnchantments
if (stored != null) stored.getEnchantments().keySet()
    .forEach(id -> config.enchantBook.put(id, containerPos));
```

### 4.2 站点坐标：只校验，不写

```
scan 时：
  grindstone: config 未设置 → problem("grindstone not set")；已设置但方块类型不符 → problem("grindstone gone at x,y,z")
  anvil:      同上（"anvil not set" / "anvil gone"）
  anvilChest / inputChest / outputChest：容器缺失 → problem("<role> chest missing at …")

扫描半径 = scanHorizontalBlocks / scanVerticalBlocks（以 BOT 为原点）；
装备框按 item 短名做 id，已存在的作业**复用**（保留手填坐标与策略）
```

### 4.3 `EquipmentType.of(ItemData)`（保留在 `AutoEnchantModule` 内，command 已有 import）

```java
public static EquipmentType of(@Nullable ItemData data) {
    if (data == null) return NONE;
    String n = data.name();
    if (n.startsWith("minecraft:")) n = n.substring(10);
    if (n.endsWith("_helmet")) return HELMET;
    if (n.endsWith("_chestplate")) return CHESTPLATE;
    if (n.endsWith("_leggings")) return LEGGINGS;
    if (n.endsWith("_boots")) return BOOTS;
    if (n.endsWith("_pickaxe")) return PICKAXE;   // 必须先于 _axe
    if (n.endsWith("_shovel")) return SHOVEL;
    if (n.endsWith("_hoe")) return HOE;
    if (n.endsWith("_sword")) return SWORD;
    if (n.endsWith("_axe")) return AXE;
    return switch (n) {
        case "bow", "crossbow", "trident", "mace", "fishing_rod", "shears",
             "flint_and_steel", "shield", "carrot_on_a_stick",
             "warped_fungus_on_a_stick", "brush", "elytra" -> valueOf(n.toUpperCase(Locale.ROOT));
        default -> NONE;   // 含 1.21.4 无 spear 的情况，不抛异常
    };
}
```

- `NONE` → 不生成作业（替代旧的 `MAX_DAMAGE` 判定；`MAX_DAMAGE` 留作二次确认）。
- `JobFrame` 增加 `EquipmentType type`，`jobDetails()` 输出 `[SWORD] diamond_sword`。

### 4.4 扫描不覆盖手改（内存签名，不写盘）

```java
private final Map<String, String> importedSignatures = new HashMap<>();  // jobId -> 词条串|名称

String sig = frame.enchantments().entrySet().stream()
    .sorted(Map.Entry.comparingByKey())
    .map(e -> e.getKey() + "=" + e.getValue())
    .collect(Collectors.joining(",")) + "|" + Objects.toString(frame.customName(), "");
if (!sig.equals(importedSignatures.get(jobId))) {
    e.itemEnchantments.clear();
    frame.enchantments().forEach(e.itemEnchantments::put);
    e.renameName = frame.customName() == null ? "" : frame.customName().trim();
    e.renameEnabled = !e.renameName.isEmpty();
    importedSignatures.put(jobId, sig);
}
```

约定：**进程重启后首次 `scan` 必重导一次**（展示框就是说明书），写进 README。

### 4.5 作业导入不变量

```
对每个 jobFrame：
  id = item 短名；同名作业已存在 → 复用，否则新建
  e.item = frame.item
  签名变化 → 重写 itemEnchantments / renameName / renameEnabled
  e.inputItemChest 未设置 → = frame 下方第一个容器
  站点 output 已发现 → 仅当 e.outputChest 未设置时写入；e.overflowChestPos 未设置 → = e.outputChest
  frame.lampOn() != null → e.enabled = lampOn
  e.postEnchantStoreMode == NONE → TO_OVERFLOW（失败品默认有地方去）
```

- `scan` 只写 config + 缓存 `markers/stations/jobFrames/problems`，不碰事务；事务中只记 pending，`POST_ENCHANT` 后应用。
- 同一 `enchantBook` key 两个书框指向不同坐标 → 保留第一个 + `problem`。

### 5.3 通用规则

- **关窗不是状态**：每个 `*_AWAIT_*` 开头 `if (!awaitContainerClosed()) return;`（照 trader），删掉 worker 里所有 `WAIT_CLOSE` / `CLOSE_*`。
- **`actionDelay`（tick）**：右击→首次点击、点击→点击的统一间隔；禁止 `Thread.sleep`。
- **`waitForInteractTimeoutTicks`**：开窗等待与铁砧/砂轮界面交互共用同一个超时（这是你定稿的语义，不要再拆两个字段）。
- **重试上限**：取货 2 / 铁砧恢复 3 / 砂轮 3（常量集中 `AutoEnchantConstants`）。
- **失败收敛**：`fail(reason)` 只做三件事 —— 记 `failureReason`、`stopOwnedKillAura()`、`setState(POST_ENCHANT)`。

### 5.4 是否需要祛魔（`EVAL_UNCHANT` 唯一判断点）

`allowGrindstone` 的语义是「**装备出箱后是否允许祛魔**」，所以判断发生在取货之后、进铁砧之前：

```
current  = 背包里该装备的词条
target   = job.itemEnchantments
impurity = current 中不在 target 里的词条（忽略诅咒；mending 等非合并项不算）

if (impurity 非空 && allowGrindstone && grindstone 就绪)  → 祛魔
else if (impurity 非空 && !allowGrindstone)              → 不祛魔，进铁砧（可能因成本 fail，fail 里注明 "impurity kept: allowGrindstone=false"）
else if (impurity 非空 && grindstone 缺失)                → fail("grindstone missing at x,y,z")
else                                                     → 不祛魔，直接进铁砧
```

### 5.5 经验（`EnchantXpFarm`）

```java
public enum Mode { NONE, KILL, EXP }        // ← config.experienceSource
boolean ensureLevels(int needed);           // 每 tick 调一次
void stopOwnedKillAura();                   // 归还
boolean consumeInterruption();
```

| Mode | 行为 |
| --- | --- |
| `NONE` | 不移动、不开 KillAura；每 `NO_XP_TIMEOUT_MS` 一条 `warn("need {} levels, waiting (experienceSource=NONE)")`，`XP_GO_TO_KILL_SPOT` 直接转 `AWAIT_RESTOCK` |
| `KILL` | 未到 `killSpot` → `BARITONE.pathTo`；到达（水平 ≤3 / 垂直 ≤4）→ `CONFIG.client.extra.killAura.enabled = true; MODULE.get(KillAura.class).syncEnabledFromConfig();` 记 `ownsActivation`；够了 → 还原原值 |
| `EXP` | 只寻路到 `killSpot`，**全程不开** KillAura，等 `experienceLevel` 上升；`NO_XP_TIMEOUT_MS` 无增长 → `warn` 并继续等 |

硬规则：
- 进 `ENCHANT_INTERACT_WITH_ANVIL` 前必须 `stopOwnedKillAura()`。
- `reset()` / `onDisable()` / 死亡 / 断线必须归还。
- 血量 < `MIN_HEALTH`(12) → 停刷 + `warn`。
- 无 `killAuraMaxSeconds` → 唯一超时是「无经验增长」。

字段名：`CONFIG.client.extra.killAura.enabled`（**驼峰 killAura**，不是 `killaura`）。

### 5.6 一件装备结束：去哪

| 结果 | 去向 |
| --- | --- |
| 成功（词条 == target） | 固定 `outputChest`（与 `postEnchantStoreMode` 无关） |
| 失败（词条不符 / 缺书 / 成本超限 / 铁砧恢复失败 / 砂轮缺失） | 固定按 `TO_OVERFLOW`：`overflowChestPos` → 未设则 `outputChest` → 都没有 **留包 + `warn`**（永不丢弃） |
| `TO_RESTOCK` | 多余输入（同物品未完批次）存回 `inputItemChest`；成品仍进 `outputChest` |
| `NONE` | 不额外卸货，靠背包满时 `STORE_*` 统一卸到 `outputChest` |

`scan` 把 `overflowChestPos` 设成与 `outputChest` 同坐标 → 默认「成品失败品同一个箱」，失败品不会混回待附魔队列（它在 output，不在 input）。

## 7. 校验器（`AutoEnchantConfigValidator`）

全局：

- `waitForInteractTimeoutTicks ∈ 1..1200`；`operationDelay ∈ 0..40`；`restartDelay ∈ 1..200`
- `anvilRestockStacks ∈ 1..8`；`scanHorizontalBlocks ∈ 1..256`；`scanVerticalBlocks ∈ 1..64`
- `experienceSource != null`
- `enchantBook`：value 非 `ZERO`，key 在 `EnchantmentRegistry` 存在
- `anvil` / `grindstone` **未设置** → `problem("anvil not set")`（提示 `autoEnchant anvil <x y z>`），不阻塞 `scan`
- 已设置但该点方块类型不符 → `problem("anvil gone at …")`，不阻塞其他作业

单作业（`problemsFor(id)`）：

- `item` 能解析到 `ItemData` 且 `EquipmentType.of() != NONE`
- `inputItemChest` / `outputChest` 已设置（`ZERO` = 未设置）
- `itemEnchantments` 非空；key 合法、`1..maxLevel`；无互斥词条
- `renameEnabled` → `renameName` 非空且 ≤50 字符
- `postEnchantStoreMode == TO_OVERFLOW && overflowChestPos 未设` → 提示（`scan` 会补，`add` 手填要警告）
- `inputItemRestockStacks ∈ 1..35`
- 预跑 `resolvePlan()`：无解（39 级上限 / 缺书 / 缺 `bookChest`）→ 直接进 `problems`，不等运行时
